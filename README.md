# RentFlow — Telegram-бот для коммунальных платежей аренды

Арендатор присылает фото счётчиков → бот читает цифры (или принимает ввод вручную) → арендатор подтверждает →
бот считает счёт → владелец проверяет и утверждает → арендатор получает расшифровку и итог → владелец отмечает оплату.

Один бинарник на Rust, SQLite, Telegram long polling (публичный адрес и HTTPS не нужны).

**Принципы:** деньги считает только детерминированный код на `Decimal`; ИИ лишь предлагает цифры и ничего не пишет в базу;
каждое показание подтверждает человек; без ключа ИИ бот работает полностью (ввод вручную).

## 1. Что нужно заранее

| Что | Где взять |
|---|---|
| Токен бота | Telegram → **@BotFather** → `/newbot` → скопировать токен |
| Ваш числовой Telegram-ID | см. шаг 3 ниже (команда `/whoami`) |
| Ключ Anthropic (необязательно) | https://console.anthropic.com → API keys. Без него фото не распознаются, показания вводятся вручную |

## 2. Запуск локально

```bash
cp .env.example .env          # впишите TELEGRAM_BOT_TOKEN (остальное можно оставить)
cargo run --release           # нужен Rust 1.97+ (rust-toolchain подтянется сам через rustup)
```

База создаётся автоматически в `data/rentflow.db`, миграции применяются при старте, фото сохраняются в `data/photos/`.

## 3. Первый запуск: узнать свой Telegram-ID

1. В `.env` оставьте `LANDLORD_TELEGRAM_ID=0` и запустите бота.
2. Напишите боту `/whoami` — он ответит вашим числом.
3. Впишите число в `LANDLORD_TELEGRAM_ID`, перезапустите бота.

Только этот ID может настраивать объект и утверждать счета. Больше никто в чужие дела не вмешается.

## 4. Настройка (один раз, владелец)

1. `/setup` — мастер задаст вопросы по порядку: название объекта, имя арендатора, дата стартовых показаний
   (можно «неизвестна» — бот её не придумывает), стартовые показания ХВС / ГВС / T1 / T2, тарифы (заводятся на текущий расчётный месяц, в какой бы день ни шла настройка) ХВС, ГВС, водоотведения (или «нет», если арендатор его не платит), T1, T2. В конце — сводка и «Сохранить».
2. `/invite` — бот пришлёт одноразовую ссылку (`https://t.me/<бот>?start=...`). Отправьте её арендатору.
   Ссылка действует 7 дней, срабатывает один раз; новая `/invite` гасит предыдущую.

Стартовые показания — это якорь для первого расчёта. Счёт за прошлое потребление они **не** создают.

## 5. Как это работает у арендатора

Арендатор открывает ссылку и нажимает «Start». Раз в месяц он:

1. Нажимает **«Ввести показания»** (или `/enter`). Бот ведёт по шагам: **ХВС → ГВС → T1 → T2**. На каждом шаге виден
   номер шага (`Шаг 2 из 4`) и прошлое показание. Число принимается сразу. Показание меньше прошлого бот не принимает
   и просит ввести заново.
2. **Прикладывает фото счётчика как подтверждение** — к каждому показанию, в любом порядке: число → фото или
   фото → число. Если владелец включил обязательное подтверждение (`/proof`, по умолчанию включено), без фото бот
   не пойдёт дальше. Если ИИ включён, он сверяет введённое число с фото и предупреждает о расхождении
   («на фото я вижу 755, а вы ввели 757»), но число не подменяет.
3. В конце бот показывает **сводку**: четыре значения, расход, пометка 📎 у тех, к кому приложено фото. Ошибся в цифре или
   не хватает фото — кнопка ✏️ рядом со счётчиком.
4. Нажимает **«Отправить показания»**. Только после этого расчёт уходит владельцу; арендатор суммы не видит до его
   подтверждения.

Если ИИ включён, фото можно прислать и **раньше числа**: цифры с него попадут в форму как подсказка (📎, при неуверенном
чтении ещё ⚠️) и проверяются на сводке. Если ИИ недоступен или не прочитал — бот просто просит ввести значение.

Одно фото нельзя использовать дважды. Фото нужно отправлять как обычное фото (не как «файл»).

`/readings` — что принято и что введено, но не отправлено. `/cancel` — отмена и удаление введённого.

## 6. Что делает владелец каждый месяц

Приходят **фото-подтверждения** (по одному на счётчик, с подписью и значением), затем черновик с построчной расшифровкой
(`стало − было = расход × тариф = сумма`) и кнопки:

- **Утвердить и отправить** — арендатор получает счёт. Повторное нажатие ничего не рассылает.
- **Отклонить** — показания периода сбрасываются, арендатор отправляет их заново.
- **Отметить оплаченным** (кнопка после утверждения или `/paid`) — арендатор получает подтверждение.

| `/enter` | арендатор | ввести показания по шагам (или кнопка «Ввести показания») |

| `/cancel`, `/help` | все | отмена текущего шага, справка |

## 7. Правила расчёта

- Из каждого накопительного показания берётся **целая часть до вычитания** (3975,48 → 3975), разница не округляется.
  Исходное значение сохраняется рядом и показывается в расшифровке.
- Водоотведение = расход ХВС + расход ГВС, отдельная строка и тариф. Включается только явно (`/setup` или `/tariff sewer ...`).
- T1 и T2 — два регистра одного электросчётчика, считаются раздельно, каждый по своему тарифу.
- **Тарифы месячные.** Тариф действует с расчётного месяца (`ГГГГ-ММ`) и дальше, пока не заменён более поздним; дат внутри
  месяца нет. Расчёт берёт тариф, действующий в расчётном месяце, **для всего месяца** — без пропорций и деления по дням.
  Тарифы не зависят от дат снятия показаний: показания 25.09 → 25.10 считаются по тарифам октября (это правило RentFlow,
  оно не обязано совпадать с правилами ресурсоснабжающих компаний). Изменение тарифа месяца заменяет его версию, а не
  добавляет вторую; водоотведение включается и выключается по тому же правилу (`/tariff sewer off [месяц]`).
- Изменение тарифов исправляет текущий расчёт: незавершённые черновики за этот и последующие месяцы пересчитываются
  (старый черновик получает статус «заменён», владелец видит новый). **Утверждённые и оплаченные счета не меняются.**
  Утверждённый неоплаченный счёт можно осознанно выпустить заново по новым тарифам: `/reissue` (старый счёт остаётся в базе
  как «заменён», арендатор получает уведомление, новый счёт утверждается отдельно). Оплаченные не перевыпускаются.
- Показание меньше предыдущего не принимается. Замена счётчика в этой версии не поддерживается.
- Расчётный месяц — месяц сообщения по `TZ_OFFSET_HOURS`. Неоконченный период продолжается, пока по нему нет счёта:
  показания разных месяцев не смешиваются.
- На период — не более одного действующего счёта (ограничение в базе).
- Одно и то же фото нельзя принять дважды.

## 8. Проблемы с сетью

Бот ходит на `https://api.telegram.org`. Если при старте вы видите `HandshakeFailure` или `timed out`, то Bot API
недоступен из вашей сети (в РФ он часто фильтруется провайдером; сам клиент Telegram при этом работает по другому протоколу).

1. Проверьте: `curl -v https://api.telegram.org/` — при блокировке тоже оборвётся рукопожатие.
2. Включите VPN или локальный прокси и укажите его в `.env`:
   ```
   HTTPS_PROXY=socks5h://127.0.0.1:1080    # или http://127.0.0.1:8080
   ```
   Поддерживаются `http://`, `https://`, `socks5://`, `socks5h://`. Лучше `socks5h://`: имя `api.telegram.org`
   тогда разрешает сам прокси (у провайдеров с фильтрацией DNS часто подменяют). Порт возьмите из настроек вашего
   VPN/прокси-клиента. На Linux/macOS, если в системе уже задан строчный `https_proxy`, он важнее — задайте обе формы.
3. Либо задайте свой адрес Bot API: `TELEGRAM_API_URL=https://ваш-зеркальный-хост`.
4. Для Docker: `docker run ... -e HTTPS_PROXY=socks5://host.docker.internal:1080 ...` (прокси должен слушать не только 127.0.0.1).

Постоянное решение — запустить бота на сервере, откуда Telegram доступен (VPS за пределами РФ).

## 9. Постоянный запуск на сервере (VPS)

Подходит любой Linux-сервер за пределами фильтруемых сетей (от ~4–5 €/мес.). Нужен только Docker.

```bash
# 1. Docker (Ubuntu/Debian)
curl -fsSL https://get.docker.com | sh

# 2. Код и настройки
git clone https://github.com/msmurygin/Rentflow.git && cd Rentflow
cp .env.example .env
nano .env        # TELEGRAM_BOT_TOKEN, LANDLORD_TELEGRAM_ID, при желании ANTHROPIC_API_KEY

# 3. Запуск (перезапускается сам после сбоя и перезагрузки сервера)
docker compose up -d --build
docker compose logs -f      # должно быть: "bot started bot_username=..."
```

Обновление: `git pull && docker compose up -d --build`. Данные (SQLite и фото) лежат в томе `rentflow-data` и
переживают обновления. Перенос существующей базы: скопируйте `data/rentflow.db` в том (бот остановлен).
Запускайте **один** экземпляр на токен — второй (например, забытый на ноутбуке) вызовет конфликты.

## 9a. Docker вручную

```bash
docker build -t rentflow .
docker run -d --name rentflow --restart unless-stopped --env-file .env -v rentflow-data:/data rentflow
docker logs -f rentflow
```

Данные (SQLite и фото) лежат в томе `/data`. **Запускайте только один экземпляр** бота с одной базой.

Резервная копия: остановите контейнер (`docker stop rentflow`) и скопируйте файл базы и каталог `photos` из тома. 
Копировать файл SQLite на работающем боте нельзя — копия может оказаться неполной.

## 9b. Mini App (v0.2)

Основной интерфейс — Telegram Mini App; бот остаётся каналом приглашений и уведомлений. Команды `/setup`, `/tariff`, `/enter`
работают как раньше (совместимость), но больше не нужны. Приложение и бот — один процесс и одна база: правила расчёта,
тарифов и утверждения общие, второй реализации нет.

**Архитектура.** `src/api/` — Axum-слой (`/api/*`): проверяет подпись `initData`, роль, права и вызывает те же сервисы `App`,
что и бот. `web/` — Svelte 5 + TypeScript + Tailwind; собирается в статику (`web/dist`), Node в production не нужен.
Caddy выдаёт HTTPS и проксирует на `rentflow:8080`, где API и статика.

**Безопасность.** Вход: `POST /api/auth/telegram` проверяет HMAC-подпись `initData` по токену бота и свежесть `auth_date`
(24 ч); идентификатор пользователя берётся только из подписанной строки. Сессия — серверная (в базе хранится хеш токена,
7 дней); роль вычисляется заново на каждом запросе. Арендатор не может менять тарифы, утверждать, отклонять, отмечать
оплату и приглашать (403); неутверждённые счета арендатору «не найдены» (404). Фото отдаются только участникам объекта.
Изменения объекта, тарифов, счетов и приглашений пишутся в `audit_log`.

**Локальная разработка без Telegram и без остановки боя.** Стенд не обращается к Telegram, поэтому не конфликтует с работающим
ботом (два polling-процесса на один токен конфликтуют — не запускайте `rentflow` с боевым токеном второй раз):

```bash
cd web && npm ci && npm run build && cd ..
cargo run --example mini_dev -- web/dist 8099     # стенд: http://127.0.0.1:8099, подписанный initData на /dev/init?user=1
cd web && node e2e/flow.mjs /tmp/shots            # сквозной сценарий владелец ↔ арендатор в настоящем Chromium + скриншоты
cd web && npm run dev                              # Vite с горячей перезагрузкой, /api проксируется на 127.0.0.1:8080
```

**Развёртывание на сервере (Hetzner).**

1. A-запись домена → IP сервера; в Cloud Firewall открыть только 80/443 (и SSH с вашего адреса). Порт 8080 наружу не публикуется.
2. В `.env`: `DOMAIN`, `MINIAPP_URL=https://<домен>`, остальное как раньше (см. `.env.example`).
3. `docker compose up -d --build` — поднимает `rentflow` (бот + API + статика) и `caddy` (HTTPS, лимит тела запроса 13 МБ).
   Бот сам выставит кнопку меню на Mini App (`MINIAPP_URL`); при желании задайте её и в BotFather (`/setmenubutton`).
4. Обновления: `deploy/deploy.sh` — копия тома (`deploy/backup.sh`, бот на секунды останавливается), сборка, перезапуск.
   Миграции базы применяются при старте (0006 добавляет `api_session` и `audit_log`).
5. Проверка: `curl -fsS https://<домен>/healthz` → `ok`, затем открыть бота → кнопка меню.

Скрипт Telegram (`web/public/telegram-web-app.js`) отдаётся с вашего домена, а не с telegram.org: в корпоративных сетях `telegram.org` бывает заблокирован. Обновить копию: `curl -fsS https://telegram.org/js/telegram-web-app.js -o web/public/telegram-web-app.js`.

Приглашение арендатора по-прежнему идёт ссылкой `t.me/<бот>?start=…`; после принятия арендатор открывает приложение кнопкой меню.

## 10. Тесты

```bash
cargo test
```

Тесты не требуют сети, Telegram и ключей: SQLite в памяти, распознавание подменено заглушкой, Telegram — заглушкой Bot API.
Покрыто: настройка и приглашения (одноразовость, срок), нулевой счёт от стартовых показаний, месячный расчёт,
раздельные T1/T2, смена тарифа, дубли фото и двойное нажатие, неполные показания, ручное исправление ошибок ИИ,
чужие объекты и карточки, обязательное утверждение владельцем и **три месяца golden dataset**
(2063,61 / 2469,51 / 2104,29 ₽, а также обнаружение расхождения 0,10 ₽ в рукописном сентябрьском листе).
Фикстуры: `tests/fixtures/golden_moscow_001/`.

HTTP API (`tests/api_flow.rs`): подделанный, чужой и просроченный `initData` → 401, незнакомый человек → 403, матрица прав
арендатора, полный месяц через HTTP (фото, ошибка ИИ и исправление, дубль фото, неполный комплект, повторная отправка,
пересчёт черновика при смене тарифа, устаревший черновик → 409, утверждение, оплата, журнал), золотая сумма 2063,61 ₽.
Фронтенд: `cd web && npm test && npm run check`; браузерный сценарий — `web/e2e/flow.mjs` (см. 9b).

## 12. Известные ограничения и что осталось до «бой»


- Распознавание **не проверено на реальном ключе и реальных фото** (ключа в среде разработки не было). Запрос построен по
  документации API и проверен на заглушке. Перед боем прогоните фото из `tests/fixtures/golden_moscow_001/photos/`
  и убедитесь, что значения читаются; пока любое значение подтверждает человек, неверное чтение не попадёт в счёт.
