# RentFlow v0.3 — Self-Service & Private Beta: changelog

**Миграции:** `0008_membership`, `0009_selfservice`, `0010_recurring` — только расширяющие (новые таблицы/колонки), данные не переписываются. Этап M5 миграций не добавляет.

## M1 Безопасность
`/void` (с причиной и подтверждением; оплаченный — только при `ALLOW_VOID_PAID=1`); `backup`/`verify-backup`/`restore`/`migrate-check` (VACUUM INTO + sha256), offsite через age+rclone, `/readyz`, алерты администратору.

## M2 Изоляция владельцев
Права берутся из `membership` (владелец/арендатор) по каждой квартире; несколько квартир на человека; чужой объект/счёт/фото → 404. `LANDLORD_TELEGRAM_ID` больше не даёт прав. Покрыто тестами `isolation`, `migration_membership` (проверено мутациями).

## M3 Самообслуживание
Регистрация владельца кнопкой, мастер настройки с возобновлением, отключаемые регистры, приглашение арендатора из приложения, выбор квартиры.

## M4 Регулярные операции
Напоминания по расписанию в часовом поясе квартиры (день передачи 29–31 = последний день месяца; срок и +2 дня); срок оплаты, просрочка и напоминания; история потребления; журнал неудачных доставок (`notification_log`) + алерт при >5 за сутки.

## M5 Готовность к бете
- **Демо:** `POST /api/demo/start` → сессия вымышленного владельца (`telegram_id<0`) с историей счетов; любая запись — 403; в Mini App кнопка «Посмотреть демо» и баннер.
  Демо-данные создаются лениво один раз, в метрики и рассылки не попадают.
- **Метрики:** `rentflow metrics` (JSON, без персональных данных): воронка квартира → арендатор → утверждённый счёт, приглашения, активные за 7 дней.
- **Лимиты:** 5 неверных приглашений / 15 мин на пользователя; ≤20 приглашений и ≤20 квартир в час; ≤10 регистраций в час; демо ≤120 стартов в час. Счётчики в памяти процесса (сбрасываются рестартом). Бот-путь `/start <токен>` лимитом пока не закрыт.
- **Приватность и инструкции:** `/privacy` в боте, `PRIVACY.md`, `BETA_GUIDE.md`.

## Известные ограничения
- Уведомления, отправляемые из API (`TelegramNotifier`), не пишутся в журнал доставки — только цикл напоминаний.
- Лимит перебора приглашений в боте (`/start <токен>`) не реализован; токены — длинные случайные.
- Выгрузка/удаление данных человека — вручную по запросу.
- Не проверено на живом сервере: offsite-скрипты, docker healthcheck, `restore-staging.sh` на копии production.

## Исправление стартовых («бутстрапных») показаний
`PUT /api/property/baselines` и кнопка «Исправить начальные показания» на экране «Квартира» (только владелец).
Разрешено, пока по квартире нет ни одного счёта (кроме отклонённых); после первого счёта — 409, т.к. якорем становится последнее принятое показание.
Старое стартовое показание не стирается (`superseded`), действие пишется в `audit_log` (`baselines_update`). Всё-или-ничего; отключённые счётчики менять нельзя.
Миграций нет. Для production-квартиры, у которой счета уже есть, это не работает намеренно: там исправление — через `/void` и пересдачу показаний.
